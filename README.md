# Luma — лаунчер

Лаунчер сети Minecraft-серверов Luma на **Tauri 2 (Rust) + React**. Интерфейс собран из дизайн-системы Luma: рейл миров, герой мира с кнопкой «Играть», друзья и пати, гардероб с 3D-скином, магазин, новости, настройки, ⌘K / Ctrl K.

## Что уже настоящее

- **Кнопка «Играть».** Скачивает и сверяет по sha512 все моды сборки (`src-tauri/modpack.json`), убирает старые, ставит Fabric 0.19.5 для Minecraft 1.21.1, создаёт профиль «Luma» в официальном Minecraft Launcher (своя папка игры, память из настроек), добавляет сервер в «Сетевую игру» и открывает лаунчер. Дальше игрок нажимает «Играть» под своим аккаунтом Microsoft.
- **Живой статус сервера** `x1.qwertyx.host:28828`: онлайн, пинг, ники игроков — тем же запросом, что и меню «Сетевая игра» в самой игре, раз в 30 секунд.
- **Скриншоты.** F2 в игре — и снимок сам появляется в лаунчере: последний — в карточке на главной, все — в альбоме (камера в левой панели или Ctrl K → «Скриншоты»). Снимок можно скопировать в буфер и вставить в Discord/Telegram, открыть, показать в папке или удалить. Лаунчер читает только папку `screenshots` игры.
- Своё окно: тайтлбар с перетаскиванием и кнопками окна (на macOS — родные «светофоры»).
- Железо компьютера в настройках; память для игры по умолчанию — половина ОЗУ, от 3 до 6 ГБ.
- Настройки и профиль сохраняются в папку приложения (`settings.json`).
- Установщик Windows в стиле Luma, на русском и английском.

## Что пока не настоящее

- Ник в самой Luma — только для лаунчера. Вход в игру делает официальный Minecraft Launcher: собственный вход через Microsoft в Luma требует, чтобы Mojang одобрила приложение (заявка на aka.ms/mce-reviewappid).
- Гардероб показывает скин только внутри лаунчера.
- Новости пишутся вручную в `src/data.js`.

Сервер и его настройки — в [`server/`](server/README.md).

## Сборка

| Что | Где | Команда | Результат в `builds/` |
|---|---|---|---|
| macOS (Apple Silicon + Intel) | Мак | `bash build-mac.sh` | `Luma_0.1.0_universal.dmg` |
| macOS + Windows | Мак | `bash build-mac.sh --windows` | + `Luma_0.1.0_x64-setup.exe` (cargo-xwin, MSVC) |
| Windows x64 | Ubuntu 24.04 | `bash build-windows-linux.sh` | `Luma_0.1.0_x64-setup.exe` (MinGW) |
| Linux | Ubuntu / Debian | `npm ci && npm run tauri build -- --bundles deb,rpm,appimage` | в `src-tauri/target/release/bundle/` |
| Всё сразу | GitHub Actions | вкладка Actions → build → Run workflow, или тег `v*` | артефакты запуска |
| Разработка | любая | `npm ci && npm run tauri dev` | окно с горячей перезагрузкой |

Нужен Rust 1.90+ и Node 18+. Для Linux-сборки: `libwebkit2gtk-4.1-dev build-essential curl wget file libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev`.

Linux-пакеты, собранные на Ubuntu 24.04, требуют glibc той же версии или новее (Ubuntu 24.04+, Debian 13+, Fedora 40+). Для дистрибутивов постарше подходит сборка из GitHub Actions — она идёт на Ubuntu 22.04.

## Админка

Вкладка с короной в левой панели видна только никам из `modpack.json` → `admins`. Сама вкладка ничего не открывает: команды уходят на сервер через RCON, и без пароля RCON они не сработают.

1. На сервере в `server.properties` задать `enable-rcon=true`, `rcon.port=<порт из раздела «Порты» QWERTYX>`, `rcon.password=<длинный случайный>` и перезапустить сервер.
2. В `src-tauri/modpack.json` вписать порт в `server.rcon`, при необходимости поправить ссылку на консоль панели в `server.panel`.
3. Админ один раз вводит пароль во вкладке. Лаунчер проверяет его на сервере и хранит в защищённом хранилище системы: Диспетчер учётных данных Windows, Связка ключей macOS, keyring ядра Linux.

Что умеет вкладка: список игроков с кнопками кик, бан (с подтверждением), OP и вайтлист; объявление в чат; быстрые команды (день, ночь, ясно, сохранить мир, TPS через spark, вайтлист, баны); консоль для любой команды с историей ↑/↓. Запуск, остановка и полный лог сервера — в панели QWERTYX: публичного API у хостинга нет, а RCON работает, только пока сервер запущен. RCON передаёт пароль без шифрования, поэтому пароль должен быть отдельным и длинным.

С Luma Cosmetics 1.2 на сервере во вкладке ещё две карточки (команды `/luma …`, нужен уровень OP 3 — у RCON он есть):

- **Бэкапы мира** — `luma backup now [комментарий]`: сервер сохраняет мир, на время архивации перестаёт писать его на диск (как `save-off`) и упаковывает в `backups/<мир>_<дата>.zip` рядом с сервером, не останавливая игру. Хранятся последние `keep` архивов (`luma backup keep <1–30>`, по умолчанию 3); при нехватке места бэкап не начнётся. Автобэкап — `luma backup auto <часы>` (0 — выключен, так по умолчанию: диск у хостинга небольшой), делается, только если кто-то играл. Вернуть мир — вручную: остановить сервер в панели, распаковать архив, заменить папку мира папкой `world` из архива, запустить.
- **Проверка сборки** — `luma mods`: с какими модами зашёл каждый игрок, его собственные моды отдельно от сборки, подозрительные (X-ray, freecam, чит-клиенты) подсвечены. Список присылает игра игрока, так что это повод присмотреться, а не античит: никого не выкидывает.

## Ветки обновлений: Юг и Север

У лаунчера две линии, и игрок выбирает свою в «Настройки» → «О лаунчере» → «Ветка обновлений».

| Ветка | Git | Тег выпуска | Релиз на GitHub |
|---|---|---|---|
| Юг | `main` | `v0.1.4` | обычный — он же «latest» |
| Север | `sever` | `sever-v0.1.4` | pre-release |

Выпуск: поднять версию в `package.json`, `src-tauri/Cargo.toml` и `src-tauri/tauri.conf.json`, закоммитить и запушить тег своей ветки (`git tag sever-v0.1.4 && git push origin sever-v0.1.4`). Actions соберёт и подпишет сборки, зашьёт в них ветку (`LUMA_CHANNEL`) и выложит `latest.json`. Юг лаунчер проверяет по «latest» (как и раньше), свежий релиз Севера находит через GitHub API. При смене ветки он предлагает её последнюю версию, даже если номер меньше. Релизы Севера помечены как pre-release, поэтому «latest» всегда остаётся Югом, и старые лаунчеры без выбора ветки на Север не перескочат.

## Главное меню игры (Luma Menu)

Свой мод для Fabric в [`menu-mod/`](menu-mod/): вместо стандартного титульного экрана Minecraft — экран Luma с островком из лаунчера под звёздным небом и кнопками «Подключиться к серверу» (сразу на сервер из `modpack.json`, со статусом онлайна), «Настройки», «Моды» (Mod Menu) и «Выйти». Огни на островке и кнопка — в акцентном цвете, выбранном в лаунчере.

С 1.1 — и меню паузы (Esc в игре): «Вернуться в игру», настройки, скриншоты, достижения, статистика, карта сервера, моды и «Отключиться», справа — кто сейчас на сервере. Пауза по F3+Esc, без меню, остаётся ванильной. Экраны подключения, загрузки местности, «Отключено» и сохранения мира рисуются на том же звёздном небе с островком.

Лаунчер ставит мод как обычный мод сборки: он записан в `modpack.json` со ссылкой на релиз `menu-v<версия>` и sha512. При запуске лаунчер передаёт игре `-Dluma.server`, `-Dluma.server.name`, `-Dluma.map` (карта для паузы) и `-Dluma.accent`. Без них, например при запуске из официального лаунчера, мод берёт сервер «Luma» из `servers.dat`, а кнопки карты нет.

Новая версия мода:

1. Поднять `mod_version` в `menu-mod/gradle.properties` и собрать: `cd menu-mod && ./gradlew build` (нужен JDK 21) → `build/libs/luma-menu-<версия>.jar`. Сборка воспроизводимая: тот же исходник даёт тот же sha512.
2. Выложить jar: `gh release create menu-v<версия> build/libs/luma-menu-<версия>.jar --prerelease`. Pre-release не трогает обновления лаунчера.
3. Обновить запись `luma-menu` в `src-tauri/modpack.json` (`version`, `file`, `url`, `sha512`, `size`) и выпустить лаунчер.

Картинки островка (`textures/gui/island_<акцент>.png`) выгружены из `VoxelArt` лаунчера, по одной на каждый акцент из `src/accent.js`.

## Плащи, питомцы, стиль и статистика (Luma Cosmetics)

Свой мод для Fabric в [`cosmetics-mod/`](cosmetics-mod/), ставится и игрокам, и на сервер. Плащ и питомца игрок выбирает в «Гардеробе», лаунчер пишет выбор в `config/luma-cosmetics.json` игры (и передаёт `-Dluma.cape`, `-Dluma.pet` для старых версий мода). Мод перечитывает файл раз в две секунды — смена в гардеробе видна и в запущенной игре. Выбор уходит серверу, сервер рассылает его всем, а новичку при входе — что надето на остальных. Принимаются только плащи и питомцы из списка, остальное сервер отбрасывает.

В логе сервера видно, кто что надел (`Luma Cosmetics: <ник> wears cape=… pet=…`) и кто зашёл без мода (`joined without the mod`) — с этого начинать, если кто-то не видит питомцев.

- Плащ подменяет текстуру плаща игрока, на элитре виден он же. Картинки плащей (`assets/luma-cosmetics/textures/cape/<id>.png`) сделаны тем же кодом, что рисует их в лаунчере (`src/cosmetics.js`).
- Питомец — модель моба, которую рисует только клиент: в мир она не добавляется, коллизий, урона и влияния на PvP нет. Когда хозяин крадётся или невидим, питомец прячется. Если рисование питомцев упадёт, мод выключит их, а не игру.
- Список id — общий контракт: `src/cosmetics.js` ↔ `Cosmetics.java`. Новый плащ — это картинка в моде плюс запись в обоих файлах.
- С 1.1 — «Стиль» в гардеробе: титул над ником, цвет ника и след (частицы у ног, пока игрок идёт). Ходят отдельным каналом (`luma-cosmetics:style`), поэтому игроки и сервер на 1.0 продолжают видеть плащи и питомцев. Корону ♛ у ника и в Tab сервер выдаёт операторам сам — клиент её не выбирает. Слова титулов — в `assets/luma-cosmetics/lang`.
- Статистика для лаунчера: раз в минуту мод спрашивает у сервера свои цифры (тот же запрос, что делает ванильный экран статистики) и пишет `config/luma-stats.json`; раз в пять минут просит у сервера таблицу лидеров (`luma-cosmetics:board_request`) — сервер собирает её из `world/stats/*.json` и памяти онлайн-игроков, не чаще раза в минуту. Лаунчер показывает это на странице «Сервер». В одиночном мире файл не пишется.

### Сервер для лаунчера (с 1.2)

Серверная часть мода публикует для лаунчера небольшие JSON-файлы в веб-папку BlueMap (`<webroot>/luma/*.json`), а BlueMap отдаёт их на порту карты — лаунчер читает их, даже когда никто не играет (`server_feed` в Rust, тестовая подмена — переменная `LUMA_FEED_DIR`). Без BlueMap мод работает, просто без этих файлов и меток. Свои данные мод хранит в `world/luma/`, настройки — в `config/luma-server.json` (`afkMinutes`, `backupAutoHours`, `backupKeep`).

- **Хроника** (`chronicle.json`): первые заходы, достижения-цели и испытания (и несколько важных обычных), смерти, победы над боссами, новые места. Строки хранятся как текст самой игры с ключами перевода, лаунчер показывает их по-русски словами из `ru_ru.json` игры (берёт из скачанных ассетов). При запуске лаунчер рассказывает, что случилось, пока тебя не было.
- **Места** (`places.json`): `/mark add <название>` отмечает место, где стоишь (до 15 на игрока), `/mark remove <название>`, `/mark list`. Метки появляются на BlueMap (набор «Места Luma») и во вкладке «Карта» лаунчера; клик по месту, строке хроники или скриншоту двигает карту (адрес BlueMap `#карта:x:y:z:…`; какая карта показывает какое измерение — `maps.json`).
- **Кто онлайн** (`online.json`) и **«отошёл»**: кто не двигался `afkMinutes` минут (или написал `/afk`), помечен в Tab, в меню паузы Luma Menu и на главной лаунчера и не считается, когда остальные ложатся спать, чтобы пропустить ночь.
- **Таблица лидеров** (`board.json`) — раз в пять минут, лаунчеру не нужно ждать, пока игрок зайдёт в игру.
- **Титулы зарабатываются**: цели считаются на сервере по статистике Minecraft (`Titles.java`, те же цели в `src/cosmetics.js`), а ещё не заработанный титул сервер не покажет, что бы ни прислал клиент. Прогресс сервер раз в минуту отправляет игре (`luma-cosmetics:titles`), она кладёт его в `luma-stats.json` для гардероба.
- **Где снят скриншот**: на F2 клиент пишет рядом `screenshots/.luma/<файл>.json` — измерение, координаты, биом, время суток, погода, кто рядом; альбом показывает это и открывает место на карте.
- **Проверка сборки**: при входе игра сообщает серверу свои моды (`luma-cosmetics:mods`); какие из них — сборка, она узнаёт из `config/luma-pack.json`, который пишет лаунчер.

Игроки и сервер разных версий друг другу не мешают: новые каналы используются, только если вторая сторона их знает.

Новая версия: поднять `mod_version` в `cosmetics-mod/gradle.properties`, `./gradlew build`, `gh release create cosmetics-v<версия> build/libs/luma-cosmetics-<версия>.jar --prerelease`, обновить запись `luma-cosmetics` в `modpack.json` и положить тот же jar на сервер в `mods/`.

## Запуск без подписи

Сборки не подписаны сертификатом разработчика.

- **Windows:** SmartScreen покажет «Windows защитила компьютер» → «Подробнее» → «Выполнить в любом случае». Нужен WebView2 — он уже есть в Windows 10 и 11, а если нет, установщик скачает его сам.
- **macOS:** на своём Маке открывается сразу. На другом — правой кнопкой по Luma → «Открыть».

## Структура

- `src/ds/` — компоненты дизайн-системы Luma (те же исходники, что в `components/bundle.js`).
- `src/screens/` — экраны: вход, главная, миры, гардероб, магазин, новости, настройки.
- `src/native.js` — мост к Rust-командам (в браузере работает на заглушках).
- `src-tauri/` — ядро на Rust, конфигурация окна и пакетов, иконки, картинки установщика (`icons/installer/`).
- `menu-mod/` — мод Luma Menu: главное меню, пауза и экраны загрузки самой игры.
- `cosmetics-mod/` — мод Luma Cosmetics: плащи, питомцы, стиль ника, следы и статистика; на сервере — хроника, места, «отошёл», титулы, бэкапы и проверка сборки.
